# Serato parity plan

This is a working plan, not a promise of identical behaviour. The goal is that a
DJ can move a library and a set of habits between OpenDeck and Serato DJ Pro
(parenthetical product reference) without losing cues, loops, grids or crates,
and that performance features behave the way the hardware expects.

OpenDeck is independent and not affiliated with Serato. Features are matched by
observable behaviour; layout, assets and wording are original.

## Principles

- Interoperate at the file-format level, not by importing Serato code.
- Match behaviour where DJs rely on it (cue slots, loop snapping, grid lock,
  crate membership). Do not chase pixel-exact layout.
- Keep every change reversible; a partial phase is reverted, not shipped
  half-wired.
- Do not break streaming, broadcast, recording or the sampler.

## Phase 0: documentation and hygiene

- `NOTICE`, this plan, `docs/interop.md`, `docs/engine.md`,
  `docs/decisions.md`.
- README links, legal section, correct EQ wording.
- No behaviour change. All existing tests pass.

## Phase 1: de-risk the playback engine

- JS/WASM worklet prototype of the planned engine: PCM ring, transport,
  reverse, sample-accurate loops, signalsmith-stretch.
- `render_offline` harness with golden and block-size-invariance tests.
- Deck public API unchanged; prototype sits behind a flag.
- Exit criterion: reverse and loops sound correct, offline renders are
  deterministic, and the existing UI still passes.

## Phase 2: Serato library round-trip

- Read cue/loop/grid/key/BPM tags for display.
- Write crates and tags with the rules in `docs/interop.md`: exact header, `wave`
  type, path matching, both marker frames, grid lock, Serato closed, temp file
  plus byte verification, undo log.
- Round-trip fixtures generated by OpenDeck; no real library files committed.
- Exit criterion: a generated library imports into Serato 4 with cues, loops and
  crates intact, and re-exporting from OpenDeck after a Serato edit preserves
  Serato's changes.

## Phase 3: engine cutover

- Rust `opendeck-audio` behind the worklet; `Deck.el` compat stub or migrated
  call sites.
- DVS and scratch use sample-accurate transport; latency is measured and the
  xrun counter is visible.
- Exit criterion: all tests green, DVS smoke test passes, recording and
  broadcast unaffected.

## Explicit non-goals

- Copying Serato source, assets, fonts, audio, manual text or visual design.
- Exact Serato pixel layout or animation timing.
- Video mixing.
- Source separation or "stems" beyond the four filter bands already present.
- Serato cloud/library sync services.
- Circumventing DRM in streaming providers.

## Verification

Each phase records what was actually verified in the README's verification
section, with the machine and versions used. Claims that were not tested are
listed as not verified rather than implied.
